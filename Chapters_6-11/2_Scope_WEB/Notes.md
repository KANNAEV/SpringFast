# 9. Области веб-видимости бинов в веб-приложениях Spring

- Кроме одиночной и прототипной, в веб- приложениях Spring доступны еще три области видимости бинов 
- Они применимы только в веб-приложениях, и поэтому их называют областями веб-видимости:
  - в рамках запроса — Spring создает новый экземпляр бина для каждого HTTP-запроса;
  - в рамках сессии — Spring создает новый экземпляр бина для каждой HTTP-сессии конкретного клиента. Этотэкземплярдоступен для всех запросов данного клиента в рамках данной сессии;
  - в рамках приложения — во всем приложении может существовать только один экземпляр такого бина. Этот экземпляр до- ступен для всех запросов от всех клиентов

## 9.1. ИСПОЛЬЗОВАНИЕ БИНОВ С ОБЛАСТЬЮ ВИДИМОСТИ В РАМКАХ ЗАПРОСА (@RequestScope)
- Использование бинов с областью видимости в рамках запроса (`@RequestScope`)
- Гарантируется, что такой экземпляр бина доступен только для данного HTTP-запроса
- Не нужно беспокоиться о проблемах конкурентности
- Имеют короткий жизненный цикл - не забиваются в памяти
- Не рекомендуется усложнять процесс за счет использования логики в конструкторе или в методе @PostConstruct
- Потому что если будет очень много запросов - это нагрузит ЦП или БД для реализации логики
---
- В примере, наш контроллер принимает метод запроса POST
- Контроллер использует бин — модель с сервисом проверки параметров запроса
- Чтобы эти данные не хранились в данной модели, помечаем ее аннотацией `@RequestScope`
- огда этот бин будет в области видимости запроса, и после его завершения — уничтожен
- `@RequestScope` может использоваться с любыми HTTP-методами (GET, POST, PUT — неважно)
- Данные в `@RequestScope` не сохраняются между запросами. Каждый раз создается новый экземпляр бина, который внедряется (инжектится) в контроллер через @Autowired или конструктор


## 9.2. ИСПОЛЬЗОВАНИЕ ОБЛАСТИ ВИДИМОСТИ В РАМКАХ СЕССИИ (@SessionScope)
- Бин с областью видимости в рамках сессии — это управляемый Spring объект который привязан к HTTP-сессии пользовавтеля.
- Даже один пользователь может отправлять конкурентные HTTP- запросы, поэтому нужно учесть возможные ситуации
- Либо избегать их, либо синхронизировать код, чтобы поддерживать конкурентность
- У каждого пользователя есть своя сессия, поэтому они получают доступ к собственным бинам, имеющим область видимости в рамках сессии
- Бины с областью видимости в рамках сессии позволяют реализовать, в частности, такие функции, как:
  - Аутентификация (пользователь имеет доступ на протяжении всей сессии)
  - Корзина интернет-магазина (Корзина запоминает все наименования, которые в нее поместил клиент)

- Для реализации сервиса аутентификации выполним следующие действия:
- У нас 2 страницы: `main.html` — для авторизованных пользователей и `login.html` — страница авторизации
- Если пользователь не авторизован, то он перенаправляется на страницу `login.html`
- Если пользователь авторизован, то он перенаправляется на страницу main.html

1) Создадим бин-сервис `LoggedUserManagementService`, который хранит имя авторизованного пользователя.
Область видимости данного бина в рамках сессии реализуется с помощью аннотации `@SessionScope`
2) Бин `LoggedUserManagementService` автомонтируется к классу-компоненту `LoginProcessor`
3) Задача `LoginProcessor` — это логика аутентификации. У него есть поле `LoggedUserManagementService`, которое инициализируется через конструктор. 
(если логин и пароль верны — устанавливает имя пользователя через сеттер в поле `loggedUserManagementService`)
4) Для страницы `main.html` создадим контроллер `MainController`, где определим действие и свяжем его с путем `/main`
5) Для каждого запроса будем проверять, хранится ли в `LoggedUserManagementService` имя пользователя
Если нет, будем перенаправлять пользователя на страницу аутентификации `login.html` с помощью `redirect:/` в return
Если имя пользователя присутствует — добавляем его в модель и отображаем `main.html`
6) Для выхода из системы передаем параметр `logout` в `GET-запрос`
7) При наличии параметра logout устанавливаем имя пользователя в null (очищаем сессию)
8) После очистки сессии перенаправляем пользователя на страницу входа

ПОСЛЕДОВАТЕЛЬНОСТЬ ДЕЙСТВИЙ ПОЛЬЗОВАТЕЛЯ

1. Пользователь открывает страницу "/"
   → Отображается login.html

2. Пользователь вводит логин "natalie" и пароль "password"
   → LoginProcessor проверяет учетные данные
   → При успехе: loggedUserManagementService.setUsername("natalie")
   → Перенаправление на "/main"

3. Пользователь попадает на "/main"
   → Проверяется loggedUserManagementService.getUsername()
   → Имя есть → отображается main.html с приветствием

4. Пользователь выходит из системы
   → Переходит на "/main?logout"
   → loggedUserManagementService.setUsername(null)
   → Перенаправление на "/"

5. Пользователь снова на странице входа



## 9.3. ИСПОЛЬЗОВАНИЕ ОБЛАСТИ ВИДИМОСТИ В РАМКАХ ВСЕГО ВЕБ-ПРИЛОЖЕНИЯ SPRING
- Не рекомендуется к киспольхованию, так как данные могут быть получены всеми пользователями различных сессий
- Такие бины доступны для всех запросов вебриложения, поэтому любая операция записи, скорее всего, будет нуждаться в синхронизации
- Лучше напрямую использовать уровень хранения данных, например базу данных.
- Используемая аннотация: `@ApplicationScope`
- На примере мы используем бин с `@ApplicationScope`  для хранения счетчика аутентификаций

```java
@Service
@ApplicationScope
public class LoginCountService {
    private int count;
    public void increment() {
count++; }
    public int getCount() {
        return count;
    }
}
```
