## Введение

- Spring многомодульный фреймворк
- Ядро Spring - SpringCore (содержит контекст для управления бинами)
- Бин - это объект java помеченный на включение в контекст приложения

## Способы добавления в контекст бинов:

### 1) Аннотация @Bean

    - создать класс конфигурации и пометить его как @Configuration

- Внутри класса добавить все нужные объекты и пометить каждый как @Bean
    - в Main функции при создании экземпляра контекста указать файл конфига

      ```java
      var context = new AnnotationConfigApplicationContext(AppConfig.class); 
      ```

- Если нужно несколько бинов 1 класса - присвой ему имя `@Bean(name = "kewa")`
- Если нужно пометить вариант бина по-умолчанию - пометь его как `@Primary`
- Аннотация @Bean удобна, когда нужен бин для класса, который не можете изменить, чтобы добавить в него
  стереотипную аннотацию

### 2) Стереотипные аннотации

- Сокращает код
- Отметить аннотацией @Component те классы, экземпляры которых вы хотите поместить в контекст Spring
- в классе конфигурации добавить путь, где искать компоненты приложения для
  контекста : `@ComponentScan(basePackages = "имя_пакета")`
- Стереотипные аннотации хороши всегда (меньше кода), а @Bean — лишь когда нет других вариантов
- Контролировать создание экземпляра можно через @PostConstructor с методом init (jakarta.annotation-api)
- Сделать что-то перед закрытием и очисткой контекста @PreDestroy (но нежелательно)
- `@Component` — базовый стереотип. Универсальная аннотация для любого Spring-компонента
- `@Service` — для сервисного слоя. Используется для классов, содержащих бизнес-логику
- `@Repository` — для DAO/репозиториев. Для классов, работающих с базой данных. (авто трансляция исключений БД в Spring
  исключения).
- `@Controller` — для веб-контроллеров. Используется в MVC для обработки HTTP-запросов (возвращает представления).
- `@RestController` — для REST API Комбинация @Controller + @ResponseBody. Используется для RESTful веб-сервисов.

- Задать дополнительные инструкции после создания бина: `@PostConstruct`
- Для этого нужно определить метод в классе компонента и снабдить этот метод аннотацией @PostConstruct
- Необходима зависимость `implementation("jakarta.annotation:jakarta.annotation-api:3.0.0")`

### 3) Программное добавление бинов (Spring 5)

- Добавление в контекст новых бинов используя существующие в контексте

```java
if (condition) {
    registerBean(b1); //Если условие истинно, добавить в контекст Spring некий бин
} else {
    registerBean(b2); //Иначе: добавить в контекст Spring другой бин
}
```

- `Supplier` — это функциональный интерфейс, который входит в пакет Java.util.function.
- Назначение реализации Supplier - возвращать заданное значение, не принимая параметров.
- Чтобы программно добавить бин в контекст Spring, достаточно вызвать метод registerBean()

```java
<T> void registerBean(
        String beanName, // Имя бина, можно указать null если оно не нужно
        Class<T> beanClass, // Класс из которого создаем бин
        Supplier<T> supplier, // чтобы возвращать значение экземпляра, добавляемого в контекст
        BeanDefinitionCustomizer... customizers); // интерфейс, для настройки различных свойств бина
```

- Шаги:

1) Создание экземпляра, который будет добавлен в контекст Spring
2) Определение Supplier, который будет возвращать этот экземпляр
3) Вызов метода registerBean(), добавляющего экземпляр в контекст Spring

### Установка связей между бинами

- Способы:

1) Непосредственно вызывая методы создающие бины (монтаж - wiring)
2) Настройка Spring чтобы он предоставлял значение через параметр метода (авто монтаж — auto-wiring)
3) Внедрением зависимостей (dependency injection, DI)

#### Монтаж бинов путем прямого вызова одного метода с аннотацией @Bean из другого такого же метода

- Заключается в вызове одного метода из другого в классе конфигурации

#### Монтаж бинов путем передачи параметра в метод с аннотацией @Bean

- Внедрение зависимостей бина путем передачи параметра в метод (dependency injection, DI)

```java
@Bean
public Person person(Parrot parrot) { // Spring внедряет бин parrot в этот параметр
    Person p = new Person();
    p.setName("Ella");
    p.setParrot(parrot);
    return p;
}
```

### ВНЕДРЕНИЕ БИНОВ С ПОМОЩЬЮ АННОТАЦИИ @AUTOWIRED

- @Autowired - пометить свойство объекта, в которое мы хотим включить значение из контекста Spring
- Помечается в классе, куда нужно внедрить зависимость
- Три способа применения аннотации @Autowired:

1) внедрение значения в поле класса
2) внедрение значения через параметры конструктора класса
3) внедрение значения через сеттер

#### @Autowired в поле класса

- Класс помечаем как стереотипный - `@Component`
- В классе над нужным полем отмечаем - `@Aurowired`
- Применяя аннотацию @Autowired к полю класса, мы даем Spring команду
  присвоить этому полю значение бина, полученного из контекста. Spring создает
  два бина, person и parrot, и внедряет объект parrot в поле бина типа Person

- Недостатки внедрения зависимостей в поле класса:
- нет возможности отметить это поле как final
- при инициализации приходится самостоятельно управлять значением, а это
  сложнее

#### @Autowired в конструкторе
- Позволяет объявлять поле как `final`
- Удобнее для тестов (не нужно надеяться что в поле будет внедрен класс)
- Просто над конструктором класса указываем @Autowired и теперь в конструктор можно передать бин
- Начиная со Spring 4.3, если класс состоит только из одного конструктора, аннотацию
  @Autowired можно пропустить

#### @Autowired через сеттер
- код сложнее читать
- нельзя пометить поле как final
- тестирование не становится проще


## ЦИКЛИЧЕСКИЕ ЗАВИСИМОСТИ
- Это ситуация когда Spring создает бин `А` - но для него нужен бин `Б`, который
  в свою очередь требует бин `А`
- Нужно обратиться к перечисленным в терминале ошибок классам и убрать циклическую зависимость

## ВЫБОР ИЗ НЕСКОЛЬКИХ БИНОВ В КОНТЕКСТЕ SPRING
- Предположим, в контексте Spring есть три бина типа Parrot
- Согласно конфигурации фреймворк должен включить значение типа Parrot в параметр
- Возможны следующие варианты:
  - Идентификатор параметра совпадает с именем одного из бинов, добавленных
    в контекст. Spring выберет бин с таким же именем, как и у параметра

  - Идентификатор параметра не совпадает ни с одним из имен бинов, имеющихся в контексте
    Тогда можно поступить так:
    - отметить один из бинов как первичный (@Primary)
    - или выбрать некий бин и отметить его аннотацией @Qualifier
  
- Автор рекомендует использовать @Qualifier
- Она подчеркивает стремление внедрить определенный бин


## 4. Контекст Spring - использование абстракций

### 4.1. ПРИМЕНЕНИЕ ИНТЕРФЕЙСОВ ДЛЯ ОПРЕДЕЛЕНИЯ КОНТРАКТОВ
- Интерфейс Java это абстрактная структура
- Применяется для объявления определенных обязанностей
- Эти обязанности даются объекту, реализующему интерфейс
- Разные объекты могут реализовывать интерфейс по разному


#### 4.1.1. Использование интерфейсов для разделения реализаций
- Допустим один класс ссылается на метод другого класса
- Если нужно поменять метод - придется редактировать оба класса 
(имена класса и методов основного класса и зависимого)
- Можно основному классу использовать интерфейс, а из интерфейса реализовать множество классов с различной реализацией
- Тогда при изменении необходимого метода - нет нужды в редактировании основного класса

#### Условие задачи
Создать приложение, с помощью которого:
команда работников управляет своими обязанностями. 
Одна из функций продукта — возможность оставлять заметки к задачам. 
Когда пользователи публикуют комментарий, он где-то сохраняется (например, в БД) 
Приложение отправляет письмо по электронке, указанному в конфигурации приложения.

#### 4.1.3. Реализация сценариев использования без применения фреймворка
- На практике объекты выполняющие условие задачи - это сервисы
- Нужен сервис реализующий сценарий "Напечатать комментарий" (CommentService)
- Объект сохранения комментария - все что работает с хранением это репозитории (CommentRepository)
- Объект отправки по электронке - все что коммуницирует с чем-то за пределами приложения это прокси (CommentNotificationProxy)
- CommentRepository и CommentRepository сделаем интерфейсами так как могут поменяться хранилища и способ отправки
- Реализуем контракты интерфейсов в DBCommentRepository и EmailCommentNotificationProxy
