# Аспекты и АОП в Spring

- Аспекты - это технология, основанная на принципе IoC
- Аспекты — это способ, которым фреймворк перехватывает вызов метода и может изменить его выполнение
- На основе аспектов реализованы многие важнейшие функции Spring
- Часто аспект используется:
    - в управлении транзакциями
    - в настройке системы безопасности, для защиты данных приложения от утечки/искажения

## 6.1. АСПЕКТЫ В SPRING

- Аспект — это просто часть логики, которую фреймворк реализует, вызывая определенные, выбранные вами методы
- При разработке аспекта нужно определить следующее:
    - Аспект - какой код должен выполнять Spring при вызове данных методов
    - Совет - когда приложение должно выполнять логику аспекта
    - Срез - выполнение каких методов перехватывать и реализовывать аспект
    - Точка соединения - это сам вызов метода

- Перехватываемый аспектом объект называют целевым объектом
- Чтобы стать для аспекта целевым, объект должен быть бином
- Если для метода определен аспект, то вызова этого метода идет через прокси-объект
- Этот прокси-объект применяет логику, описанную в аспекте, и затем делегирует вызов исходному методу
- Требуемая зависимость: spring-aspects

## 6.2. РЕАЛИЗАЦИЯ АСПЕКТОВ В SPRING С ПОМОЩЬЮ АОП

Задача:
Предположим, что есть некое приложение с классами сервисов, реализующими многочисленные сценарии
использования. В соответствии с новыми требованиями приложение:

- должно запоминать время начала и конца выполнения каждого сценария
- Функционал по записи в журнал всех событий старта и окончания сценариев использования

## 6.2.1. Реализация простого аспекта

- Шаги создания аспекта:
    - Активация механизма аспектов - аннотация @EnableAspectJAutoProxy в классе конфигурации
    - Создать новый класс с аннотацией @Aspect и поместить этот класс в контекст (@Bean
      Стереотипно)
    - Определите метод, в котором будет реализована логика аспекта, и с помощью аннотаций советов
      сообщите Spring, где и какие методы следует перехватывать
    - Реализовать логику аспекта

- @Around, сообщает Spring, какой метод нужно перехватить
- Ему передается строковое выражение на языке AspectJ
- Он определяет - какие методы нужно перехватывать
- @Aspect("execution(* services.*.*(..))")
    - execution - при вызове метода
    - Далее в скобках - какие методы перехватывать
    - \* перехватываемый метод может возвращать значение любого типа
    - services.* - перехватываемый метод в пакете services в любом классе
    - .* - у метода может быть любое имя
    - (..) метод может иметь разные параметры
- Параметр ProceedingJoinPoint в классе-аспекте определяет перехватываемый метод
- сли не использовать proceed(), аспект никогда не будет делегировать управление перехваченному методу
- метод proceed() выбрасывает исключение Throwable proceed()
- рассчитан на то, чтобы выдавать любое исключение, поступающее от перехваченного метода
- при необходимости можно обработать его с помощью блока try-catch-finally

## 6.2.2. Изменение параметров и возвращаемого значения перехваченного метода

- Аспекты так кже могут :
    - перехватывать параметры, использованные при вызове метода и модифицировать их
    - модифицировать возвращаемое значение методом

---

- Пример: нам нужно записывать в журнал параметры, используемые при вызове метода сервиса,
  а также то, что этот метод возвращает:
- Нам понадобится ссылка на то, что возвращает метод (добавим return в CommentService )
- Любую информацию о перехватываемом методе (параметры, имя, целевой объект) можно получить с помощью параметра
  ProceedingJoinPoint
