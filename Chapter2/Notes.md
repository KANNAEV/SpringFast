# Введение в Spring Boot и Spring MVC

- База, на которой строятся веб-приложения

## 7.1. ЧТО ТАКОЕ ВЕБ-ПРИЛОЖЕНИЕ

- Сейчас практически все нужные нам приложения — это веб-приложения.
- Разработчику крайне важно уметь их создавать

### 7.1.1. Основные сведения о веб-приложениях

- Любое веб-приложение состоит из двух частей:
    - Клиентская часть (frontend) - Представлена веб-браузером
    - Серверная часть —(backend) - получает запросы от клиента и отправляет ему в ответ данные
- Клиентов может быть много, и неправильный код серверной части может создавать состояния гонки на запросы клиентов

### 7.1.2. Способы реализации веб-приложений на основе Spring

- Веб-приложения по способу функционирования бывают разные
    - Backend в ответ на запрос клиента дает полностью готовое представление (В качестве ответа Backend предоставляет
      содержимое в виде HTML, CSS, а также в других форматах, которые браузер способен интерпретировать и вывести на
      экран). Применяется в основном для разделения уровня ответственности в сложных проектах.
    - Приложения с разделением обязанностей между Backend и Frontend (Backend отправляет только первичные данные (обычно
      представленные в JSON или XML). Браузер запускает клиентское приложение, которое получает первичный ответ от
      сервера, обрабатывает его и выводит данные). Применяется в основном для небольших приложений.

### 7.1.3. Использование контейнера сервлетов в веб-разработке

- Веб-браузер обменивается данными с сервером по сети через протокол HTTP
- HTTP аккуратно регламентирует данный процесс
- Контейнер сервлетов служит для Java-приложения переводчиком с HTTP
- Одним из самых популярных контейнеров сервлетов считается Tomcat
- Контейнер сервлетов умеет «говорить на языке HTTP». Он переводит HTTP-запрос для Spring-приложения, а ответ
  приложения — в HTTP-ответ. Благодаря этому можно не беспокоиться, какой протокол используется для передачи данных по
  сети, — достаточно представить все в виде объектов и методов Java
- Сервлет — это просто объект Java, который напрямую взаимодействует с контейнером сервлетов
- Если объект сервлета определен в Spring-приложении и зарегистрирован в контейнере сервлетов, и Spring, и контейнер
  знают о его существовании и могут им управлять

## 7.2. МАГИЯ SPRING BOOT

- Spring Boot — инструмент для создания современных Spring-приложений (и в 2026 году)
- Опции и возможности SpringBoot :
    - Упрощенное создание проектов (сервис инициализации)
    - Диспетчеры зависимостей (группировка всех необходимых зависимостей с помощью диспеетчеров)
    - Автоконфигурация на основе зависимостей

### 7.2.1. Создание проекта Spring Boot с помощью сервиса инициализации проекта

- Сервис инициализации помогает создать проект,который затем можно будет импортировать в любую IDE

1) Откройте в браузере страницу https://start.spring.io
2) Укажите свойства проекта (язык, версию, систему сборки и т п )
3) Укажите зависимости, которые нужно добавить в проект
4) Загрузите упакованный проект с помощью кнопки GENERATE
5) Распакуйте проект и откройте его в IDE

- Для следующего примера создадим такой проект с подключением компонента Spring Web
- @SpringBootApplication - аннотация, которая помечает класс главным в Spring приложении
- В файле конфигурации сборщика проекта (в нашем примере Maven) pom.xml .

- Блок <parent> для Spring Boot Maven (`spring-boot-starter-parent`)
- добавлен родительский узел Spring Boot
- Он может выводить сообщение о совместимых версиях зависимостей, которые будут добавляться в проект.

```XML pom.xml
<parent> 
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.3.4.RELEASE</version>
    <relativePath/>
</parent>
</parent>
```

- Плагин Spring Boot Maven ( `spring-boot-maven-plugin`)
- Отвечает за дополнительные части стандартной конфигурации,

```XML pom.xml
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
```

- Зависимости Maven
- `spring-boot-starter- web` - Это диспетчер зависимостей
- Во всех созданных нами примерах мы указывали версию каждой зависимости. Здесь это не понадобится, поскольку Spring
  Boot выбирает нужную версию автоматически Именно для этого в pom.xml есть родительский узел Spring Boot:

```XML
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

- `application.properties`- в папке ресурсов служит для настройки параметров, необходимых в процессе выполнения
  приложения.
